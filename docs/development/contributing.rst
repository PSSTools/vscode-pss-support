Contributing
============

Prerequisites
-------------

- **Node.js** 18 or newer (Node.js 22 recommended). Use ``nvm use 22`` if
  available.
- **Python** 3.x — for ``ivpm``, which fetches the parser.
- **Java** 11 or newer — used while building the parser: pssparser's C++ front
  end is generated by ANTLR, which is a Java tool. Nothing in this repository
  runs ANTLR itself.

Project Structure
-----------------

.. code-block:: text

   vscode-pss-support/
     client/                     # VS Code extension client
       src/extension.ts          # Extension entry point
     server/                     # Language server
       src/
         core/                   # Pure logic layer (no LSP/VS Code deps)
           ast/                  # AST node types and utilities
             generated/          # Re-export of the AST classes in @psstools/pssparser
           index/                # WorkspaceIndex: parses and links the workspace
           parser/               # Parser session and marker translation
           services/             # Document symbols, hover, completion, etc.
           types/                # Model types (Diagnostic, SourceRange, …)
           io/                   # I/O abstraction interfaces
         lsp/                    # LSP protocol handlers
         server.ts               # Server entry point
       test/                     # Tests mirroring the src/ structure
       bench/                    # Benchmarks
       vitest.config.ts          # Test configuration
     packages/                   # Fetched by ivpm; not tracked in git
       pssparser/                # The parser; ts/ builds to @psstools/pssparser
       python/                   # ivpm-managed virtualenv

Build Steps
-----------

The server does not contain a parser. It parses through
``@psstools/pssparser`` — the pssparser C++ core compiled to WebAssembly, with
a TypeScript API — which ``ivpm`` fetches into ``packages/pssparser`` and npm
builds from source there. ``server/package.json`` names it by ``file:`` path,
so **a fresh clone will not even install until you bootstrap**.

The build is npm's, not ivpm's: ``packages/pssparser/ts`` declares a
``prepare`` hook, and npm runs it when installing a ``file:`` dependency. That
hook is what drives cmake, Emscripten and ``tsc``. There is no build
declaration in ``ivpm.yaml`` and there should not be.

This is deliberate: the PSS language moves, and building the parser from
fetched sources means an upstream change surfaces as a CI failure rather than
as a vendored copy that silently falls behind.

.. code-block:: bash

   # Fetch pssparser, build the WebAssembly parser, install everything.
   # Requires Python 3 (for ivpm) and Java 11+ (pssparser's front end is
   # generated by ANTLR during the build).
   npm run bootstrap

   # Thereafter, to pick up an upstream parser change:
   ivpm update -a -d default-dev -j 1

   # Compile TypeScript
   npm run compile

   # Run core tests
   npm run test:core

No pssparser version is pinned. If a grammar or AST change upstream breaks the
build here, that is the intended signal — fix the consumer, do not pin the
dependency.

Running Tests
-------------

.. code-block:: bash

   cd server

   # All tests
   npx vitest run

   # Core tests only (there are no vitest projects; the split is by path)
   npx vitest run test/core

   # Watch mode
   npx vitest

   # Benchmarks
   npx vitest bench --run

Architecture Constraint
-----------------------

The ``server/src/core/`` directory must **not** import from
``vscode-languageserver``, ``vscode``, or any other LSP/editor library.
This is enforced by an ESLint ``no-restricted-imports`` rule. The core layer
must be testable in isolation without any editor dependencies.

Code Style
----------

- TypeScript strict mode is enabled.
- Compilation target: ES2020.
- Indent: 2 spaces.
